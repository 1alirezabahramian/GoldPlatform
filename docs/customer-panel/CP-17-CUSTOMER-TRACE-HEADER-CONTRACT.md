# CP-17 — Customer Trace Header Contract

## هدف

قابل‌پیگیری‌کردن پاسخ‌های Customer API برای پشتیبانی و عیب‌یابی، بدون افشای اطلاعات داخلی.

## قرارداد

تمام پاسخ‌های استاندارد موفق و خطای Customer API باید شناسه همان درخواست را در Header زیر برگردانند:

- `X-Request-ID`

همان مقدار همچنان در Envelope پاسخ نیز باقی می‌ماند.

## منبع شناسه

شناسه فقط از `request_id` تولیدشده و ثبت‌شده در Request Context خوانده می‌شود. مقدار خام Header ورودی کاربر مستقیماً مبنای پاسخ قرار نمی‌گیرد.

## مرزهای ایمنی

- بدون Migration
- بدون تغییر Rule مالی
- بدون Wallet، Ledger یا Settlement
- بدون Kimia Read/Write
- بدون افشای Stack Trace یا شناسه داخلی مالی

## اعتبارسنجی مستقل

این Stage پس از Merge شدن CP-16 روی Branch مبنای اصلی قرار گرفته و باید شش Gate استاندارد CI را روی SHA مستقل خود با موفقیت طی کند.
