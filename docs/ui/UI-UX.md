# رابط کاربری و تجربه کاربری GoldPlatform

پایه مشترک Design System، RTL، نمایش دقیق اعداد و حالت‌های Loading/Error/Stale در
[`DESIGN_SYSTEM_FOUNDATION.md`](DESIGN_SYSTEM_FOUNDATION.md) ثبت شده است. این سند هنوز
Framework یا رنگ و فونت نهایی را انتخاب نمی‌کند.

## ورود و انتخاب بستر حساب

وضعیت: قرارداد نسخه فعلی به‌همراه مسیر پیشنهادی آینده

### نسخه فعلی

1. مشتری شماره موبایل یکتای خود را در Tenant جاری وارد می‌کند؛ قید فعلی دیتابیس تا
   Migration مرحله‌ای کاربران هنوز موقتاً سراسری است.
2. ورود با OTP تکمیل می‌شود.
3. اکانت واردشده حداکثر به یک `AccountId` کیمیا متصل است.
4. مشتری فقط مانده، امانات، سفارش‌ها و معاملات همان حساب را مشاهده می‌کند.
5. `AccountId` و اصطلاحات حسابداری در رابط مشتری نمایش داده نمی‌شوند.

تغییر شماره موبایل یا کد ملی، ویرایش مشخصات مشتری است و نباید اتصال حساب مالی را
بی‌صدا تغییر دهد. صفحات و ضوابط امنیتی تغییر شماره موبایل هنوز طراحی نشده‌اند.

### ورود چندحسابی در آینده

در نسخه‌ای آینده می‌توان پس از شناسایی یا ورود با موبایل یا کد ملی، فهرست حساب‌هایی
را که شخص مجاز به استفاده از آن‌هاست نمایش داد و پیش از ورود نهایی، انتخاب حساب را
الزامی کرد.

این جریان فعلاً فقط یک جهت طراحی آینده است. تا زمانی که Backend موارد زیر را تعریف
نکرده، Frontend نباید چنین قابلیتی را فعال یا در دسترس نشان دهد:

- رابطه شخص/هویت با حساب‌های مستقل؛
- روش اثبات مالکیت یا مجوز استفاده از هر حساب؛
- قواعد Session و Token برای حساب انتخاب‌شده؛
- Audit Log انتخاب یا تعویض حساب؛
- قواعد استفاده مجدد یا تکرار احراز هویت KYC.

فهرست آینده باید نام یا عنوان قابل‌فهم حساب را نمایش دهد و شناسه خام Kimia را به
مشتری نشان ندهد.
